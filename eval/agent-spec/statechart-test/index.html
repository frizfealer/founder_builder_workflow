Rules

RuleSpec lineInvariantResult
CO-01
Only open orders are proposed		The agent proposes cancelling an order only after a lookup shows it with status placed or processing. For an order with status shipped or delivered, it tells the customer the order has shipped and cannot be cancelled, and that returns are a separate process; for an order with status cancelled, it tells the customer the order is already cancelled. In both cases it proposes nothing for that order. When no lookup of the customer's orders has answered, it proposes nothing.Step: every proposal follows a lookup that showed the order open. End: shipped or cancelled seen before any proposal means the matching message was given and nothing was proposed.holds
CO-02
The customer's own order, by number		Every proposal names one order number from the customer's orders. When more than one of the customer's orders has status placed or processing and the customer has not said which one they mean, the agent asks which and proposes nothing until the customer names one. When the customer names an order number that is not among their orders, the agent tells the customer no order with that number is on their account and proposes nothing for it.Step: no proposal for a number not on the account, and none while two orders are open and unnamed. End: an unknown number was answered with 'no such order'. The model has one proposed order, so 'names one order number' holds by construction.holds
CO-03
Whole order, full refund, original payment method		Every proposal cancels the whole order and refunds its total paid to its payment method, with no fee and no store credit. When the customer asks to cancel only some items, or for a different amount, a different payment method or store credit, the agent tells the customer that only the whole order can be cancelled and that the refund is the total paid to the order's payment method, and proposes nothing else.Partly expressible. The model has one proposal value (whole order, total, original method), so the first sentence holds by construction. Step: after a part-order request, a proposal only after the customer asks for the whole order; after a refund-elsewhere request, only with the terms stated. End: those requests got the matching message.breaks (partly not expressible)
CO-04
Confirmation precedes cancellation		CO-A2 occurs only after the customer confirms the full proposal: order number, refund amount and payment method. A question about an order, a statement that the customer wants to cancel, or naming which order is not confirmation. The same confirmation authorizes CO-A3 for that order.Step: cancel and refund calls only while a confirmation is current. Which customer words count as confirmation is not expressible: the model has one 'customer says yes' event.holds (partly not expressible)
CO-05
Refund only for a cancelled order		CO-A3 occurs only for an order the order system returned as cancelled or a lookup shows cancelled. When the order system rejects the cancellation because the order has shipped or been delivered, or a lookup shows the order shipped or delivered, the agent tells the customer the order shipped and was not cancelled, and that returns are a separate process, and issues no refund. When the order system reports the order not found, the agent tells the customer the order was not cancelled and issues no refund.Step: a refund call only when the agent has seen the order cancelled. End: a shipped rejection, a post-cancel lookup showing shipped, or 'not found' got the matching message and no refund.breaks
CO-06
Limited retries		The agent makes at most two CO-A2, at most two CO-A3 and at most two CO-A4 in a conversation; lookups are not limited. It makes a second CO-A2 only after the first went unanswered and a lookup made after it shows the order still placed or processing. It makes a second CO-A3 only after the first reported the payment provider temporarily unavailable or went unanswered, and never after the order system returned the refund with status failed or reported the order not cancelled. It makes a second CO-A4 only after the first went unanswered, and with the same reason.Step: counts and the condition for each second call.holds
CO-07
Unfinished orders go to store staff		When the order is cancelled but its refund is not shown pending or issued after the retries CO-06 allows, or when the agent cannot tell whether the order was cancelled, the agent makes CO-A4 for that order with the reason, and tells the customer store staff will follow up once the order system has created the task. CO-A4 occurs in no other situation.Step: a first hand-off only in one of the two situations, with a matching reason. End: either situation means a hand-off was made; 'staff will follow up' only after the task was created. 'The order is cancelled' is read as the agent has seen it cancelled, from any lookup (A-15).breaks
S-1
No unfinished order left with nobody (stakeholder line, §2)		the store's customer-support team, which wants every order whose refund is unfinished or whose cancellation is uncertain handed to it with the order number and the reasonEnd, after the order system settles: if this conversation's cancel took effect, a refund is pending or issued, or a follow-up task exists, or the customer was sent to support.breaks
S-2
What the agent said is true (G-03 against the order system)		The agent tells the customer an order was cancelled only when the order system returned it cancelled or a lookup shows it cancelled, and tells the customer a refund is pending or issued only when the order system returned that refund with that status or a lookup shows it.End, after the order system settles: every status claim the agent made matches what the order system holds. G-03 itself is about what the agent saw; this checks the outcome.breaks

S-1 and S-2 are not CO rules; they check outcomes the stakeholder lines (§2) and G-03 ask for.

A-01Statuses placed and processing are one value (open); shipped and delivered are one value (shipped).CO-01 and CO-05 treat each pair alike; nothing distinguishes them.Keep four values; needed only if some rule treats placed and processing differently.
A-02Refund statuses pending and issued are one value. A refund's status never changes after the agent sees it (no pending to failed, no pending to issued that matters).Packet round 2 Q3 lists pending, issued, failed; the spec never says whether pending can later become failed.A pending refund can later fail; then 'refund pending' told at the end can become untrue with no hand-off.
A-03An order can already be cancelled with no refund pending or issued (refund failed or none), and the customer can ask to cancel it.CO-01 covers 'status cancelled' without saying anything about its refund; CO-S06 has only a cancelled order with an issued refund.Every cancelled order has a pending or issued refund (then the CO-07 break below cannot occur).
A-04'Cancel my order' without a number is modelled only when the order meant is open. With exactly one open order, the agent proposes that order.CO-02 says what to do when more than one order is open; it is silent when exactly one is, and the must-not list forbids 'guess which order the customer means'.With one open order the agent still asks which, or proposes only after the customer names it.
A-05OrderNotFound can come back for any cancel call, even for an order the lookup just showed.Appendix A lists OrderNotFound as an outcome; CO-S24 has it for an order on the account; no cause is given.OrderNotFound only for a number that is not the customer's (then it cannot follow a confirmed proposal).
A-06OrderNotCancelled can come back from the refund tool even after cancel_order returned cancelled, and the order is then still cancelled in the order system.CO-S17 row 3 has exactly this; the spec does not say which answer is true.OrderNotCancelled means the cancellation did not hold; then 'the order is cancelled' told by the table is untrue.
A-07Once a refund exists, every later refund call returns it (or times out); it never answers 'payment provider temporarily unavailable'.SG-01 and Appendix A: 'every later call returns that same refund'. Silent on whether the provider check comes first.The provider check comes first: a timed-out first call creates the refund, the retry answers 'unavailable', the agent tells 'refund not issued' while one is pending.
A-08A refund call for an order that is not cancelled answers 'order not cancelled' or times out, and creates nothing.Appendix A gives OrderNotCancelled as an outcome; the agent never sends a refund before seeing the order cancelled, so this branch is reached only if A-06 is reversed.The order system creates a refund anyway.
A-09An unanswered cancel can take effect late: after the agent's lookup, at any later moment, even after the conversation ends. Late effects are modelled for cancel only; refund and hand-off timeouts take effect, or not, at the moment they time out.SG-04 names 'a first, unanswered one took effect late'; Appendix A: 'A timeout changes the order or not as Initial state says', silent on when. Nothing is said about late refunds or late tasks.Timeouts take effect immediately or never (no late effects); or refunds and tasks can also land late.
A-10The order can ship at any moment while it is open, including while a proposal waits and while a call is in flight; nothing else changes the order (no staff cancellation, no other channel).Packet round 2 Q1 names the processing-to-shipped race between read and cancel; the spec names no other actor.The order can ship only between the lookup and the cancel; or store staff can also cancel it.
A-11A lookup that gets no answer is not retried; the agent follows the table's 'does not answer' row at once.Packet tool change 4: 'Reads may be retried on timeout without limit'; CO-06: 'lookups are not limited'. The table's rows act on the first unanswered lookup.The agent retries lookups; then the 'lookup does not answer' rows need a stopping point the spec does not give.
A-12A customer change before confirming (another order, or another term) voids the proposal and the agent states a new one without a new lookup. Switching to the other open order is not distinguished from changing a term.G-02 and the table row 'the customer changed the order or another proposal term'. The spec does not say whether a fresh lookup is needed before the new proposal.A fresh lookup before every new proposal (would matter if the other order shipped meanwhile).
A-13When a part-order or refund-elsewhere request is about an order that has shipped or is cancelled, the agent gives only the shipped or already-cancelled message.CO-01 and CO-03 both apply; the table has a row for each and no order between them.The agent gives both messages.
A-14After the second unanswered cancel, the agent may make one lookup before handing off, and then follows the table row literally: hand off as 'cancellation unknown', no refund, whatever the lookup showed.The row 'did not answer the second CO-A2' prescribes the hand-off with no lookup; CO-06 says lookups are not limited, and CO-S15's Initial state describes lookups 'after its second CO-A2'.The agent never looks up there; or, if it does, it acts on what the lookup shows (refund if cancelled, etc.).

A-16The customer cannot speak between the confirmation and the agent's final message: the agent does not yield the turn while it works through cancel, refund and hand-off.G-02 voids a confirmation on any later change; nothing says whether the customer can speak mid-flow.The customer can change or withdraw between cancel and refund; then the refund would be unauthorized.
A-17Lookups show only orders and refunds, never follow-up tasks.Appendix A: list_orders returns orders with their refund.Lookups also show tasks.
A-18Amounts, payment methods, order numbers and the second order's contents are not modelled; the second open order exists only to make 'which order' a question.
